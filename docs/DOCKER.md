# MGO в Docker

Для NAS, Portainer и Linux нужен Docker Compose v2 на x86-64. Создайте проект
из [compose.yaml](../compose.yaml), разверните стек и откройте
`https://<адрес NAS>:8443`. Встроенный сертификат можно заменить доверенным
или добавить в доверенные на клиенте. [Настройка HTTPS](HTTPS.md)

Вход по токену в стандартном стеке отключён. Размещайте шлюз в доверенной
домашней сети. Для обратного прокси на той же машине используйте
`MGO_BIND=127.0.0.1`, укажите публичное имя в `ALLOWED_ORIGINS` сервиса
`app` и защитите доступ на стороне прокси. Дополнительное подтверждение доступа
можно настроить через `AUTH_TOKEN` в окружении API.

## Папки на NAS

- По умолчанию игры, настройки и сохранения лежат в томе `mgo-data`.
  Для bind mount используйте `MGO_DATA=/volume1/docker/mgo/data`. Укажите
  `PUID` и `PGID` пользователя с правом записи в эту папку.
- Если уже есть каталог игр, укажите его в `MGO_LIBRARY`. Штатный Compose монтирует каталог с правом записи для загрузок Java ME.
  Папки для Java ME, N-Gage и SIS и подпапка загрузок задаются в Settings → Game library.
- Если игр ещё нет, мастер предлагает **Curated Java ME library**. [Библиотека](LIBRARY.md)
- Symbian и N-Gage требуют вашу прошивку. Для больших архивов можно подключить
  хостовый каталог через `SYMBIAN_INBOX`. [Прошивки](SYMBIAN.md)

Опциональные переменные подключения и томов перечислены в [.env.example](../.env.example).
Для установки из Portainer их можно указать в Environment либо отредактировать
соответствующие строки YAML. Дополнительные лимиты API можно задавать в
`services.app.environment` через override.

## Данные и резервные копии

Библиотека, настройки, сохранения игр (RMS), SoundFont, файлы игр и журналы лежат в `/data` контейнера: в томе `mgo-data` или в папке `MGO_DATA`. Сохраняйте этот том при обновлении.

Резервная копия (на время копирования лучше остановить приложение — база SQLite):

```bash
docker compose stop app
# папка MGO_DATA:
tar czf mgo-backup-$(date +%F).tgz -C /volume1/docker/mgo data
# или том Docker:
docker run --rm -v mgo_mgo-data:/data -v "$PWD":/backup alpine tar czf /backup/mgo-backup-$(date +%F).tgz -C /data .
docker compose start app
```

Папку `MGO_DATA` можно включить в Hyper Backup / Snapshot Replication / любое резервное копирование NAS. Восстановление: остановить, распаковать архив в то же место, запустить.
Прошивки Symbian лежат в томе `mgo_mgo-symbian-data` (не удаляйте его и включите в резервную копию; прошивки принадлежат вам, MGO их не хранит).
Команды `mgo` (update, backup, doctor) в Docker нет — она есть только в контейнере Proxmox.

## Обновление

```bash
docker compose pull
docker compose up -d
```

В Synology Container Manager: *Проект → mgo → Действие → Сборка* (скачивает новые образы и пересоздаёт контейнеры). С `MGO_VERSION=latest` обновление берёт самый новый выпуск; перед обновлением сделайте резервную копию. Откат — вернуть прежний номер в `MGO_VERSION` и выполнить `docker compose up -d`.

Приложение и шлюз по умолчанию следуют последнему стабильному выпуску (`latest`). Параметр `MGO_VERSION` закрепляет оба образа на выбранной версии. У приложения есть дополнительная группа `10` для общих папок на UGREEN NAS. Сохраняйте имя проекта, пути и тома при обновлении. Для отключения входа используйте актуальный Compose. Явно заданный в старом стеке `AUTH_TOKEN` действует, пока этот параметр передаётся в приложение. EKA2L1 использует закреплённую сборку `sha-494f03e`; его тег меняется отдельно через `MGO_SYMBIAN_VERSION`.

## Обновление KEmulator из настроек

Откройте **Settings → System → KEmulator** и нажмите **Check for updates**. MGO предложит более новую сборку с Bridge из последнего стабильного релиза MGO. Пакет называется `mgo-kemulator-v…-bridge1-linux-amd64.zip`. Docker-шлюз получает каталог и пакет с GitHub через внутренний порт `9090`. В стандартном Compose для этого используется `MGO_METADATA_GATEWAY`. На установках без шлюза MGO обращается к GitHub напрямую. Для отдельного шлюза можно указать `MGO_RELEASE_PROXY_URL`.

Новая сборка сохраняется в `/data/kemulator-runtime` и используется при следующем запуске игры Java ME. **Restore bundled version** возвращает версию из образа. Текущий сеанс продолжает работу со своим ядром до остановки. При обновлении самого MGO встроенная сборка получает приоритет, если её версия не ниже установленной через Settings.

В `v2.22.1` можно включить **Preload resources** в параметрах совместимости игры. Предзагрузка увеличивает расход памяти при запуске. Сетевой режим Bluetooth из upstream не включён в интерфейсе MGO.

## Доступ извне и HTTPS

Стандартный стек доступен в локальной сети по HTTPS. Если нужен доступ снаружи — VPN (WireGuard/Tailscale) либо обратный прокси с TLS:

1. В `compose.yaml`: задайте `MGO_BIND=127.0.0.1` и пропишите `ALLOWED_ORIGINS: https://mgo.example.com` для сервиса `app` (или используйте необязательный `.env`).
2. Прокси (Synology: *Панель управления → Портал входа → Обратный прокси*; Caddy; nginx) направляет `https://mgo.example.com` на `https://127.0.0.1:8443` и **пропускает WebSocket** (заголовки `Upgrade`/`Connection`; в Synology — вкладка «Пользовательские заголовки → WebSocket»). Таймаут чтения — не меньше часа.
3. **Размер запроса.** У большинства прокси лимит по умолчанию мал (nginx и Nginx Proxy Manager — 1 МБ, Synology — свой). Для обычной работы это не мешает, но **загрузка игр Symbian/N-Gage (до 512 МБ) и прошивок (до 2 ГБ)** упрётся в `413 Request Entity Too Large` уже на вашем прокси: поднимите лимит (nginx: `client_max_body_size 4g;` и `proxy_request_buffering off;` для `/api/games` и `/api/symbian/`) и проверьте путь командой `node tools/symbian/check-upload.mjs https://mgo.example.com --mb 600 --token …` — [подробности](SYMBIAN.md#лимиты-загрузки). Cloudflare Tunnel/прокси на бесплатном тарифе пропускает тело не более 100 МБ: такие файлы кладите в каталог (см. «Прошивка из папки»).

Копирование снимка экрана в буфер обмена браузер разрешает только на страницах по HTTPS (или с `localhost`); сохранение файлом работает всегда.

## Сеть игр

В `compose.yaml` приложение подключено только к внутренней сети Docker без маршрута наружу: игра не может обратиться ни в интернет, ни к вашему NAS и принтерам. Это защита, а не неполадка. Игре из старого каталога нужен интернет (счёт, реклама)? Осознанно:

```bash
docker compose -f compose.yaml -f compose.egress.yaml up -d
```

Игра сможет обращаться ко всему, что доступно контейнеру, включая вашу локальную сеть. Включайте только для игр, которым доверяете.

## Безопасность

* Контейнер приложения работает не от root, с файловой системой «только чтение», без привилегий (`cap_drop: ALL`, `no-new-privileges`), с лимитами памяти, процессов и CPU.
* Порт публикует только шлюз (nginx) — приложение изолировано во внутренней сети.
* Подробности и известные пробелы — [SECURITY.md](SECURITY.md).

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| В журнале `EACCES`, `permission denied` или `Data directory /data is not writable` | В `services.app.user` задайте UID:GID с правом записи в каталог NAS или вернитесь к Docker volume `mgo-data:/data` и `10001:10001`; подробнее см. выше |
| `port is already allocated` | порт 8080 занят: `MGO_PORT=8090` |
| Страница открывается, но игра не стартует, в журнале нет места | мало памяти: проверьте `services.app.mem_limit`, закройте лишние контейнеры |
| `denied` / `unauthorized` при загрузке образа | пакеты на `ghcr.io` должны быть публичными — владелец репозитория включает это один раз (*Packages → Package settings → Change visibility*) |
| Интерфейс за обратным прокси: «белый экран» / нет картинки | не пропускается WebSocket или не задан `ALLOWED_ORIGINS` |
| За пределами локальной сети нет звука | звук включается после первого нажатия на странице (требование браузера) |

В **Настройки → Система** рабочий объём памяти приложения считается без
неактивного файлового кеша, как в `docker stats` на Linux. Отдельно показаны
полный объём по cgroup, кеш и число завершений процессов из-за нехватки памяти,
если ядро публикует эти счётчики. EKA2L1 работает в отдельном контейнере и
показывает свои показатели отдельно.

Журналы: `docker compose logs -f app`. Отчёт для сообщения об ошибке: в плеере — *Session → Download diagnostics* (в образе есть `jcmd`, поэтому в отчёт попадают куча и потоки JVM).

## Сборка из исходников

```bash
git clone https://github.com/grayhex/MGO && cd MGO
docker compose -f compose.yaml -f compose.build.yaml up -d --build
```

Только `compose.build.yaml` включает сборку из исходников; обычный `compose.yaml` использует готовые GHCR-образы. Первая сборка занимает 10–20 минут (клонируется и собирается KEmulator, компилируется Rust-адаптер). Образ использует закреплённый коммит KEmulator и патчи из `runtime/patches`; других внешних исходников в репозитории нет.

### Сетевой доступ к метаданным

Шлюз должен разрешать DNS и иметь исходящий HTTPS к GitHub, Internet Archive,
Hugging Face (J2ME Vault и его CDN), My Abandonware, All About Symbian и MobyGames. Стандартный Compose задаёт для API
`MGO_METADATA_GATEWAY: http://gateway:9090` и подключает шлюз к сети
`edge`. При обновлении старого стека обновите оба образа и перенесите новые
настройки шлюза. При ошибке DNS, таймауте или HTTP 502 проверьте доступ к
My Abandonware из контейнера шлюза. Открытие сайта в браузере проверяет
сетевой путь самого браузера.

```bash
docker compose exec gateway wget -Y off -S -O /dev/null http://127.0.0.1:9090/java-sources/www.myabandonware.com/game/batman-begins-wg7
docker compose logs gateway
```

JAR и EKA2L1 продолжают работать во внутренних сетях.

### J2ME Archive в Docker и на NAS

Для установки индекса и ручной загрузки JAR используйте совместимые версии
образов приложения и шлюза. Обычный `compose.yaml` включает маршруты архива
на внутреннем шлюзе и хранит базу в `/data/j2me-archive`. Сетевой оверлей для
эмулятора включать не требуется. Для следующей установки индекса оставьте не
менее 1,2 ГиБ свободного места сверх существующей базы.

`MGO_LIBRARY` в штатном Compose монтируется с правом записи. Если старый
Compose содержит `:/mnt/mgo-library:ro`, смените его на `:/mnt/mgo-library:rw`
и пересоздайте контейнер. У процесса с `PUID:PGID` должны быть права записи.
В настройках библиотеки выберите папку Java ME и сохраните относительную
подпапку загрузок, например `Curated Java ME`. Приложение показывает полный
путь назначения. При отсутствии папки Java ME загрузки идут в постоянный
том под `/data/import`. Файловая система назначения должна поддерживать hard links.

В бэкап постоянного тома можно не включать восстановимый `j2me-archive/`.
Сохраните `library.sqlite`, `games/`, `saves/` и, если нужны исходные
скачанные файлы, `import/`. [Порядок работы](LIBRARY.md#архив-сборок-java-me)
